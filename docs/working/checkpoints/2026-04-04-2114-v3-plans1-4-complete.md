- **readme MCP tool** — returns full usage guide with all CLI commands. Addresses Claude.ai not surfacing MCP server `instructions` field (model only sees tool names/descriptions).

## Architecture Decisions Made During Implementation

1. **CLI distribution via KV** — bundled JS served from Worker at `/cli/skillport.js`. 746ms download vs ~5s npm install. Self-updates via `/cli/version` check.
2. **Proxy-aware HTTP** — Claude.ai sandboxes require egress proxy. Node's fetch doesn't support it. `execFileSync("curl", ...)` is the only reliable cross-environment approach.
3. **Plugin-level vs skill-level operations** — `list`, `info`, `save`, `deactivate`, `reactivate`, `delete` all operate at plugin level. `get` operates at skill level (downloads one skill's files). `info` tries plugin first, falls back to skill.
4. **Synthesized plugin.json** — skill-level `.claude-plugin/plugin.json` is generated at download, not stored in repo. Eliminates version sync problems. Plugin-level is the single source of truth.
5. **readme MCP tool** — Claude.ai only shows tool names/descriptions, not server instructions. A dedicated `readme` tool gives the model a reliable way to learn the full workflow.
6. **Plugin layout detection** — CLI detects `skills/` subdirectory to choose between `PUT /api/plugins/:name` (whole plugin) and `POST /api/skills/:name` (standalone skill) for save operations.
